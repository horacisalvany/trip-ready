4. Firebase Paths Reference

Path Purpose Access
users/{uid}/lists/{listId} Private lists owned by the user Owner only
users/{uid}/groups/{groupId} Item groups (templates for sections) Owner only
users/{uid}/sharedListIds/{listId} References to shared lists Owner read/write; any auth user can write (to add share ref)
sharedLists/{listId} Shared list data (title, sections, sharedWith) Owner + users in sharedWith
userEmails/{sanitizedEmail} Email-to-UID lookup (dots replaced with commas) Any authenticated user can read; write own entry

5. Key Design Decisions

Decision Rationale
Copy list to sharedLists/ Firebase RTDB doesn't support per-node ACLs on nested paths. Top-level node enables security rules based on ownerUid and sharedWith.
Store references at sharedListIds/ Avoids querying all of sharedLists/ to find lists for a user. Each user has a lightweight index.
Sanitize emails (dot to comma) Firebase keys cannot contain ., #, $, [, or ]. Commas are allowed and reversible.
Register email on every login Ensures the lookup table stays current even if a user changes their display name or re-authenticates.
